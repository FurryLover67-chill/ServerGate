# ServerGate — общий пароль на вход (Paper 1.21.1)

Игрок заходит на сервер и до ввода пароля превращается в «овощ»: ослеплён, заморожен, не видит чат и других игроков, не может ничего делать. Единственное, что ему доступно, — команда `/gate <пароль>`. После правильного пароля работает как обычно (дальше AuthMe просит `/login` или `/register`).

## 1. Сборка плагина (получение .jar)

Нужен файл `ServerGate-1.1.0.jar`. Два способа:

**Способ А: на своём компьютере**
1. Установите JDK 21 (например, Temurin) и Apache Maven.
2. Распакуйте архив, откройте терминал в папке `ServerGate`.
3. Выполните `mvn clean package`.
4. Готовый файл: `target/ServerGate-1.1.0.jar`.

**Способ Б: без установки программ (GitHub)**
1. Создайте репозиторий на github.com и загрузите в него содержимое папки `ServerGate` (вместе с `.github`).
2. Откройте вкладку **Actions**, дождитесь окончания сборки «Build».
3. Скачайте артефакт `ServerGate` — внутри будет `.jar`.

## 2. Установка через FileZilla

1. Откройте FileZilla → **Файл → Менеджер сайтов → Новый сайт**.
2. Протокол: **SFTP** (если хостинг даёт только FTP — выберите FTP). Укажите хост, порт, логин и пароль из панели хостинга. Нажмите **Соединиться**.
3. В правой панели (сервер) откройте папку `plugins`.
4. В левой панели (ваш компьютер) найдите `ServerGate-1.1.0.jar` и перетащите его в `plugins` справа.
5. **Полностью перезапустите сервер** (не `/reload`).
6. Проверьте консоль: должна появиться строка про ServerGate и предупреждение «Пароль НЕ задан» — это нормально.

## 3. Задание пароля

1. В FileZilla откройте `plugins/ServerGate/config.yml` (правый клик → **Просмотр/Правка**).
2. Впишите пароль **в одинарных кавычках**:
   ```yaml
   password: 'мой секретный пароль #1!'
   ```
   Одинарную кавычку внутри пароля удвойте: `'it''s'`. Подойдут любые символы, пробелы и эмодзи.
3. Сохраните файл (FileZilla спросит про загрузку на сервер — подтвердите).
4. В консоли сервера выполните `sg reload` (или перезапустите сервер).
5. Откройте `config.yml` ещё раз: поле `password` стало пустым, а `password-salt` и `password-hash` заполнены — значит пароль надёжно сохранён в виде хеша.

Альтернатива: в **консоли** сервера `servergate setpassword любой пароль со пробелами` (из игры эта команда не работает).

## 4. Настройка AuthMe (важно)

Откройте `plugins/AuthMe/config.yml`:

- `settings.restrictions.allowCommands` — добавьте `/gate` и `/gpass`.
- `settings.restrictions.timeout` — увеличьте до `180` (иначе AuthMe кикнет игрока за 30 секунд, пока тот вводит общий пароль).
- Перезапустите сервер или выполните `/authme reload`.

Порядок входа: **/gate пароль → /login (или /register) в AuthMe**.

## 5. Использование

**Игрок:**
1. Заходит на сервер, видит затемнённый экран и надпись.
2. Вводит `/gate <пароль>` (пароль можно с пробелами).
3. После успеха экран проясняется и появляется обычный вход через AuthMe.

**Администратор:**

| Команда | Что делает |
|---|---|
| `/servergate reload` (`/sg reload`) | Перечитать конфиг |
| `/servergate setpassword <пароль>` | Сменить пароль (только консоль) |

Право `servergate.admin` — управление плагином (по умолчанию у операторов).
Право `servergate.bypass` — вход без пароля, например через LuckPerms:
`/lp user Ник permission set servergate.bypass true`

**Основные настройки `config.yml`:** `max-attempts` (попыток до блока IP), `ip-lockout-seconds`, `timeout-seconds`, `bypass-ops`, `hide-password-from-log`, `allowed-commands`, `messages`.

## 6. Безопасность — что важно знать

- **Шифрование трафика даёт только `online-mode=true`.** В этом режиме всё, включая `/gate`, шифруется. При `online-mode=false` (частый случай с AuthMe) шифрования нет, и пароль виден при перехвате. Решение — прокси (Velocity/BungeeCord) с `online-mode=true` перед сервером либо VPN/туннель. Плагин сам этого сделать не может.
- Пароль хранится только в виде PBKDF2-хеша с солью. Перехватить `/gate` на сервере другие плагины не смогут: команда отменяется до их обработки.
- Фильтр лога скрывает строки `issued server command: /gate ...`. После установки сделайте тестовый вход и **проверьте `logs/latest.log`**: пароля там быть не должно. Плагины-«шпионы» за командами (CommandSpy и подобные) могут записывать команды сами, исключите из них `/gate`.
- Клиент Minecraft запоминает введённые команды в истории (стрелка вверх): игрокам не стоит оставлять пароль на виду.
- Если пароль не задан, плагин никого не пускает на сервер (защита от случайно открытого сервера).

## 7. Проверка после установки

1. Зайдите вторым аккаунтом: экран затемнён, ходить, бить, открывать инвентарь, писать в чат нельзя.
2. Введите неверный пароль — счётчик попыток уменьшается; после `max-attempts` неудач вас кикнет и IP заблокируется.
3. Введите верный пароль — доступ открыт, остальным показано сообщение о входе.
4. Проверьте `logs/latest.log` на отсутствие пароля.

## 8. Если что-то не работает

- **Плагин не загрузился** — нужна Java 21 и Paper 1.21.x; смотрите консоль на ошибки.
- **«Unknown command» при `/gate`** — проверьте, что плагин включён (`/plugins`), и нет другого плагина с командой `gate`.
- **AuthMe кикает за таймаут** — увеличьте `settings.restrictions.timeout`.
- **Пароль с особыми символами не принимается** — Minecraft вырезает управляющие символы и `§`; используйте обычные символы.
